Prototypes

Five ways to show what the Ractor models say

Each page below draws the same TLA+ models in a different way. The readers know neither TLA+ nor Ractors. Every state and every step on these pages comes from the state graphs that TLC checked.

mainP1T1
workerT3

Theatre

Short animated stories. Each story plays one path through a model: a thread waits, a message arrives, a port closes, a worker ends. A caption explains each step and shows the Ruby call.

Teaches
What Ractors, ports, and blocking calls do.
Best for
A first visit, talks, and the top of each model page.

Explorer

You choose what happens next. The page lists every call that is possible in the current state. You guess the outcome, then watch it. A meter shows how much of the state space you saw.

Teaches
That a model is a set of states and allowed steps; where the specification leaves CRuby a choice.
Best for
Readers who learn by trying.

Multiverse

The whole state graph grows level by level, the way TLC explores it. Then the paths that ran on CRuby light up one by one until every transition is covered.

Teaches
What model checking and replay mean, and why the result is exhaustive within the bounds.
Best for
Explaining the method, not the API.

Rule cards

One card per rule, with a small looping animation, the outcome, the Ruby that triggers it, and whether the documentation states the rule.

Teaches
The rules themselves, at a glance.
Best for
Reference use, and links from documentation and issues.

Timelines

Swimlanes for the worker pool: each of the 80 schedules plays as jobs move between main and two workers. A second view splits the timeline at fork.

Teaches
Order and interleaving: what can run before what.
Best for
Protocols with several Ractors, and process-level events.
